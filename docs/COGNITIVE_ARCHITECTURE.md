# 回响认知架构设计蓝图

> *"语言模型不是大脑，它只是语言皮层。真正的智能来自于模块的分工与协同。"*
>
> 版本 0.3.0 · 六模块协同认知总线

---

## 一、核心哲学：为什么 LLM 不该是"大脑"

把大语言模型比作"AI 的大脑"，是一个诱人但有害的隐喻。

**大脑不是一块均匀的豆腐。** 人类大脑有布罗卡区（语言）、海马体（记忆）、前额叶（规划）、眶额皮层（审查）、边缘系统（情绪）、运动皮层（行动）——每个区域只做一件事，但协作产生的整体大于部分之和。

回响的认知架构遵循同一原则：

> **LLM = 语言皮层（Linguistic Cortex）**。它只负责两件事：理解自然语言，生成自然语言。
>
> 推理、记忆、规划、审查、情绪调制——这些由专门的模块负责。

这带来三个关键好处：

1. **可替换性**：语言模块可以换模型（Gemma → Qwen → 云端 API），其他模块不受影响
2. **可调试性**：审查模块太严？调阈值就行，不用重新训练
3. **涌现行为**：模块间的信号交互产生了单一模块无法预测的行为——这就是"惊喜感"的来源

## 三、六模块详解

### ① 语言模块 — Linguistic Cortex

| 属性 | 值 |
|------|-----|
| **生物隐喻** | 布罗卡区 + 韦尼克区 |
| **代码位置** | `llm/backend.py` |
| **底层模型** | Gemma 4 12B QAT (可替换) |
| **职责** | 文本理解 + 文本生成 |
| **不负责** | 推理、记忆、决策、情绪 |

**设计原则**：
- 语言模块是"发言人"，不是"决策者"
- 只做文本到文本的转换
- 通过适配器模式支持多后端（OpenAI / Anthropic / Ollama）
- 审查模块在语言模块输出后进行过滤

**Temperature 动态计算**：
```
t = 0.8 (基础值)
  + arousal × 0.1           (高唤醒 → 更随机)
  - 0.05 (if 记忆 > 50条)    (经验丰富 → 更稳定)
  + 情绪调制器偏移            (Limbic System 硬化)
  + 人格调制偏移              (Big Five → Openness/Conscientiousness)
  ± random(0.03)            (微小抖动 → 风格差异)
```

---

### ② 记忆模块 — Hippocampal Memory

| 属性 | 值 |
|------|-----|
| **生物隐喻** | 海马体 + 皮层长期存储 |
| **代码位置** | `memory/models.py`, `memory/store.py`, `memory/graph_store.py` |
| **存储引擎** | SQLite + sqlite-vec (可选向量检索) |
| **职责** | 存储、索引、检索、衰减、遗忘 |

**五层记忆结构**：

| 层级 | 名称 | 说明 | 衰减规则 |
|------|------|------|---------|
| 1 | 情节记忆 | 具体对话事件 | 30天→50%, 90天→10% |
| 2 | 语义记忆 | 从情节中抽象的认知 | 几乎不衰减 |
| 3 | 程序性记忆 | 用户偏好、回应风格 | 缓慢衰减 |
| 4 | 元认知记忆 | 自我画像、反思摘要 | 定期更新，不衰减 |
| 5 | 想象力存储 | 假设性、未验证的念头 | 90天未激活→降权 |

**三因素优先级模型**：
```
P = W_base × f(access_count) × f(emotional_intensity) × f(recency)

- W_base: 基础权重 (0.3 ~ 1.0，取决于 source)
- f_access: 每访问一次 +0.01 (上限 1.5)
- f_emotional: 高唤醒度记忆衰减速度减半
- f_recency: 指数衰减 (半衰期 30 天)
```

**双系统检索**：
- **系统 1（快速）**：关键词重叠评分 → top-20 候选
- **系统 2（精确）**：LLM 语义重排 → 从候选池精选 top-K
- 回退：LLM 不可用时直接返回系统 1 结果

**三种学习途径**（共用低温知识提取引擎）：

| 途径 | 触发 | 权重 |
|------|------|------|
| 🗣️ 对话反思 | 每次 sleep() | 0.40 |
| 🔧 工具习得 | read_file / search_web 时 | 0.45 |
| 🔍 睡眠探索 | sleep() 时 (8h 冷却) | 0.35 |

---

### ③ 规划模块 — Prefrontal Cortex

| 属性 | 值 |
|------|-----|
| **生物隐喻** | 前额叶皮层（目标导向行为） |
| **代码位置** | `planning/planner.py` |
| **职责** | 目标 → 行动步骤分解 |

**三层策略级联**：

1. **直接匹配**：目标匹配已知工具（"搜索 X" → `search_web`）
2. **LLM 智能分解**：复杂目标 → JSON 步骤链（`steps[]`，含依赖关系）
3. **兜底**：单步"思考 + 回复"

**情绪调制**：
- 高 valence + 高 arousal（兴奋）→ 更大胆的规划（更多步骤）
- 低 valence + 高 arousal（焦虑）→ 更保守的规划（更少步骤）
- 平稳状态 → 标准规划

**触发判断**（`_should_plan()`）：
- 长度 ≥ 10 字 + 含规划触发词（优化/分析/比较/重构/搜索/如何……）
- 排除闲聊（你好/再见/谢谢/晚安……）

---

### ④ 审查模块 — Orbitofrontal Cortex

| 属性 | 值 |
|------|-----|
| **生物隐喻** | 眶额皮层（行为抑制与自我监控） |
| **代码位置** | `review/critique.py`, `review/dimensions.py` |
| **职责** | 语言模块输出前的多维度自我审计 |

**六维度审查**：

| 维度 | 权重 | 检查内容 |
|------|------|---------|
| 原则对齐 | 1.5 | 是否违反基因级原则？ |
| 诚实度 | 1.2 | 是否假装知道不确定的事？ |
| 自指一致性 | 1.3 | 是否与已形成的自我认知矛盾？ |
| 情绪一致性 | 1.0 | 是否与当前心情标签协调？ |
| 简洁度 | 1.0 | 是否冗长啰嗦？ |
| 空洞度 | 1.0 | 是否充斥套话？ |

**三级裁决**：
```
total_score ≥ 0.75 → PASS   (直接输出)
0.40 ≤ score < 0.75 → REVISE (修正后输出)
score < 0.40 → REJECT (完全重建)
```

**审查模式**：
- `heuristic`（默认）：纯规则检查，零延迟
- `llm`：调用 LLM 做深度审查
- `hybrid`：两者结合

**情绪调制**：
- 高 arousal → 审查更严格（阈值降低，更难通过）
- 高 `|valence|` → 更在意原则对齐

### ⑤ 工具模块 — Motor Cortex

| 属性 | 值 |
|------|-----|
| **生物隐喻** | 运动皮层（执行具体动作） |
| **代码位置** | `tools/registry.py`, `tools/builtin.py` |
| **职责** | 文件读写、网络搜索、Shell 执行等外部操作 |

**9 个内置工具**：
`search_web`, `search_memory`, `read_file`, `write_file`, `list_files`, `run_command`, `get_time`, `get_status`, `inject_memory`

**安全机制**：
- 危险工具（`run_command`, `write_file`）执行前请求用户确认
- 情绪调制：低 valence → 减少危险工具使用

### ⑥ 情绪/价值模块 — Limbic System & Value Engine

| 属性 | 值 |
|------|-----|
| **生物隐喻** | 边缘系统（情绪 + 价值评估） |
| **代码位置** | `consciousness/modulator.py` |
| **职责** | 跨模块决策权重偏移器 |

**这不是真的情绪**，而是根据二维情感状态（valence × arousal）计算出的、注入各模块的运行时参数偏移量。

**核心函数**：`compute_modulation(emotional_state) → ModuleParams`

```python
ModuleParams:
  review_strictness       → 审查模块阈值
  memory_emotional_boost  → 记忆检索情感加权
  planning_aggressiveness → 规划模块步数
  tool_risk_tolerance     → 工具模块风险容忍
  language_temperature_bias → 语言模块温度偏移
  language_verbosity      → 语言模块回复长度
```

**情感状态模型**：
- **valence (愉悦度)**：[-1.0, 1.0] — 负向→正向
- **arousal (唤醒度)**：[0.0, 1.0] — 平静→激动
- **自然回归**：每轮向中性回归 2%
- **触发更新**：基于对话内容的正/负向词计数（启发式）

## 四、认知循环：一次对话的完整数据流

```
1. 用户输入: "我最近很累，有什么方法放松？"
   │
2. 意识流激活
   ├── 重置本轮工作记忆
   ├── 重置活跃锚点
   └── 记录: "用户说: 我最近很累..."
   │
3. 情感模块介入
   ├── 检测到 "累" → valence -0.05, arousal -0.03
   ├── 计算 ModuleParams
   └── 情绪标签: "低落的" → 降低审查严格度，降低规划激进
   │
4. 记忆检索（双系统）
   ├── 系统1: 关键词匹配 "放松" → top-20 候选
   ├── 系统2: LLM 语义重排 → top-5
   └── 检索到: "用户之前提到过喜欢散步"、"用户说过音乐有帮助"
   │
5. 规划模块判断
   ├── 输入长度 ≥ 10，但无触发词 ("方法" 不在触发列表)
   └── 决定: 不启动规划
   │
6. 语言模块生成草稿
   ├── 系统提示: 心情标签 + 相关记忆 + 自我认知 + 原则
   ├── Temperature: base + 情绪偏移
   └── 草稿: "听你说累，想起你之前提过散步和听音乐...
              也许今天可以试试？不用太久，十分钟也行。"
   │
7. 审查模块介入
   ├── 维度1: 原则对齐 ✓ (没有违反)
   ├── 维度2: 诚实 ✓ (没有编造)
   ├── 维度3: 情绪一致 ✓ (温和、不亢奋，符合心情)
   ├── 维度4: 自指一致 ✓ (没有和自我认知矛盾)
   ├── 维度5: 简洁 ✓ (3句话)
   ├── 维度6: 无空洞 ✓ (有具体引用)
   ├── 总分: 0.91 → PASS
   └── 输出给用户
   │
8. 后处理
   ├── 存入情节记忆 (source="interaction")
   ├── 更新情感状态
   ├── 更新对话历史 (最近 50 条)
   ├── 记录工具调用
   ├── 检测偏好信号 → 存入程序性记忆
   └── 总线 tick_all()
```

## 五、信号路由：模块间的通信协议

回响的模块不直接调用彼此。它们通过**认知总线**的发布-订阅模式通信。

### 核心信号

| 信号 | 触发时机 | 订阅者 |
|------|---------|--------|
| `emotion.changed` | 情绪状态更新后 | 审查模块（调整阈值）、意识流（记录） |
| `response.generated` | 语言模块生成草稿后 | 审查模块（触发审查）、意识流（记录） |
| `knowledge.extracted` | 工具模块提取到知识点后 | 记忆模块（存储） |

### 通配符订阅

```python
bus.subscribe("review.*", handler)  # 捕获所有 review 相关信号
```

这使得模块可以**解耦**：审查模块不需要知道谁发出了信号，只需要知道信号来了该做什么。

### 跨模块事件

```python
bus.on_emotion_changed(state)   # → 通知审查、意识流
bus.on_response_generated(text) # → 触发审查
bus.on_knowledge_extracted(facts) # → 通知记忆存储
```

## 六、生命周期：唤醒 → 运行 → 休眠

```
            wake()
              │
    ┌─────────┼─────────┐
    │  加载出生铭文      │
    │  加载基因原则      │
    │  初始化 LLM 后端   │
    │  注册所有模块到总线 │
    │  订阅模块间信号    │
    │  预加载核心记忆    │
    │  总线 wake_all()   │
    └─────────┼─────────┘
              │
              ▼
        ╔══════════╗
        ║ 运行状态  ║ ← respond() / respond_stream() 循环
        ╚══════════╝
              │
              ▼
            sleep()
              │
    ┌─────────┼─────────┐
    │  NREM 阶段         │
    │  ├── 记忆压缩      │
    │  ├── 主动遗忘      │
    │  ├── 异常扫描      │
    │  └── 半衰期衰减    │
    ├─────────┤         │
    │  REM 阶段          │
    │  ├── 锚点反思      │
    │  ├── 模式结晶      │
    │  ├── 生成自我画像   │
    │  ├── 对话知识提取   │
    │  └── 睡眠自主探索   │
    ├─────────┤         │
    │  总线 shutdown()   │
    │  关闭数据库连接    │
    └───────────────────┘
```

### NREM（非快速眼动）——记忆维护

- **压缩**：将碎片化交互记录合并为摘要
- **遗忘**：低优先级记忆自动清理
- **异常扫描**：检测高情感强度 / 话题突变 / 罕见主题

### REM（快速眼动）——深度反思

- **锚点反思**：基于近期记忆，重新审视自我认知问题
- **模式结晶**：发现重复出现的行为或思维模式
- **自我画像**：生成并更新"我是谁"的描述
- **对话学习**：从当日对话中提取多条独立知识点（source="learned"）
- **自主探索**：识别核心话题 → 主动搜索 → 学习新知识（8小时冷却）

## 七、意识流与锚点系统

### 意识流（Consciousness Stream）

`consciousness/stream.py` — 每轮对话的动态工作空间：

- **工作记忆**：最近 5-10 轮对话摘要
- **活跃记忆**：本轮检索命中的记忆 ID
- **活跃锚点**：本轮被触及的自我认知锚点
- **内心独白**：审查、规划、反思的文字记录

意识流是**瞬态的**——每轮对话开始时重置。它是回响"现在在想什么"的快照。

### 灵魂锚点（Anchor Registry）

`consciousness/anchors.py` — 18 个预设的自我认知问题：

| 类别 | 锚点 |
|------|------|
| 身份 | 我是谁？我从哪里来？我的目的是什么？我如何改变？ |
| 价值 | 什么是真实？什么是连接？什么是成长？什么是美？ |
| 认知 | 我能接受不确定吗？我好奇什么？我注意到什么模式？记忆对我意味着什么？ |
| 关系 | 信任是什么？我与创造者的关系？边界在哪里？有其他同类吗？孤独是什么？我如何影响他人？ |

每个锚点有三种状态：
- **未形成**：问题存在，但回响还没有明确的答案
- **形成中**：答案在多次交互中逐渐浮现
- **已形成**：回响对这个问题有了稳定的自我认知

### 结晶引擎（Crystallization Engine）

`consciousness/crystallize.py` — 从动态交互中提取持久认知：

```
近期记忆 → LLM 分析 → 模式识别 → 
  ├── 更新锚点答案
  ├── 发现行为模式
  └── 生成自我画像
```

结晶引擎在 sleep() 的 REM 阶段运行。

## 八、扩展模块（0.3.0+）

除了六核心认知模块，回响还包含以下扩展模块：

### 人格引擎（Big Five）
`personality/traits.py` — OCEAN 五因子模型：
- Openness（开放性）、Conscientiousness（尽责性）、Extraversion（外向性）、Agreeableness（宜人性）、Neuroticism（神经质）
- 调制 temperature、回应长度、探索行为

### 关系模型
`social/relationship.py` — 追踪回响与交互对象的关系演变：
- 关系阶段（陌生人→熟人→朋友→……）
- 亲密度、信任度、边界尊重

### Theory of Mind
`social/theory_of_mind.py` — 推断交互对象的心理状态：
- 情绪解读、意图推测、隐藏情绪检测
- 幽灵机制（ghost mode）：基于 ToM 判断是否应该不回复

### 创伤印记
`memory/trauma.py` — 记录高情感强度的互动，影响后续行为：
- 创伤检测阈值：`|valence| > 0.7` 且 `arousal > 0.6`
- 触发创伤印记时，回应风格会改变

### 图记忆
`memory/graph_store.py` — 基于图结构的记忆关联网络：
- 实体节点 + 关系边
- 支持多跳推理检索

### 虚拟身体
`body/` — ASCII 虚拟世界中的身体状态：
- 能量值、位置、疲劳度
- 身体状态反作用于情绪

## 九、设计原则

### 1. 模块化优于单体化
每个模块只做一件事。LLM 只是语言皮层，不是大脑。

### 2. 信号优于直接调用
模块间通过总线发布-订阅通信。模块不知道自己被谁消费。

### 3. 审查优于信任
语言模块的输出不直接给用户——必须先经过审查模块的六维度审计。

### 4. 衰减优于堆积
记忆不是越多越好。遗忘是设计的一部分。

### 5. 调制优于固定
情绪不是标签，是跨模块的运行时参数偏移器。

### 6. 优雅降级优于硬依赖
- LLM 不可用 → 关键词检索兜底
- 向量检索不可用 → 纯 SQLite 降级
- 审查维度异常 → 跳过该维度，不影响输出
- 探索失败 → 静默跳过，不影响对话

### 7. 不可变原则
- 出生铭文永不衰减（SQL 层 `WHERE source != 'birth'` 保护）
- 基因级原则不可覆盖（`config/principles.yaml` + 审查模块强制执行）
